# 数据模型设计（未来规范库，不是当前运行库）

可执行定义见 schema-v2.sql。当前 v0.3.0 使用 notes / history / note_revisions 三张本地表；其中 note_revisions 记录并发版本，详见《笔记备份与冲突-v0.3》。本文件其余内容是未来规范库，需要独立迁移任务才能上线。

## 关系和字段约定

| 数据组 | 表 | 作用 / 关键约束 |
| --- | --- | --- |
| 项目归属 | workspaces → projects → roots → files | 工作区有项目，项目有多个根目录；文件按 root_id + path_key 唯一。复合外键防止文件串项目。 |
| 语言 | project_languages | 一种语言一行，不再用逗号字符串。 |
| 术语 | terms、term_aliases | 内置词条与项目词条分域；scope_key 非空，避免 SQLite NULL 导致重复；同一词可按语言有不同含义。 |
| 笔记 | annotations、annotation_tags | 文件外键、起止位置、偏移、快照、代码 / 文件哈希、状态、作者和时间；标签一行一个。 |
| 分区 | region_rules | 路径 / 正则 / AST 规则、层级和优先级；表达式须由服务限时验证，禁止直接执行输入。 |
| 后台任务 | jobs | 状态、进度、幂等键、错误码和时间；同项目同请求键只能有一个任务。 |
| 问题与修复 | health_issues、diagnostics、fix_previews、fix_history | 绑定文件内容版本；过期结果不能继续应用；诊断与修复分开。 |
| 地图 | flow_graphs、flow_nodes、flow_edges | 边的两端必须属于同一个项目、同一张图；保留依据和置信度。 |
| 导览 | guide_paths、guide_steps | 步骤序号在同一路径内唯一；引用真实文件，不保存未经校验的绝对路径。 |
| 知识图谱 | knowledge_entities、knowledge_relations、embeddings | 实体有来源；关系有依据；向量独立存二进制并记录模型、维度与内容哈希。 |
| 团队知识 | kb_entries、kb_tags | 元数据索引；Markdown 文件是共享正文的真源；同步冲突需显式处理。 |
| AI 会话与同意 | chat_sessions、chat_messages、consent_records | 对话按项目归属；发送同意绑定内容哈希、提供方和到期时间；不存 API 密钥。 |

ID 为 UUID 字符串；时间为 UTC ISO 8601 字符串。数据库约束限制基本形状，ID / 时间格式由接口验证。显示时转换为本地时间。version 是大于 0 的递增整数，每次写入原子加一，用来检测两个窗口同时编辑。

坐标统一为 **0 起始、UTF-16、结束位置不包含在选区内**；UI 显示时行号加一。startOffset/endOffset 必须与行列指向同一个原始文本；遇到 emoji 不按 UTF-8 字节或 Unicode code point 混算。换行按原文件保留；代码哈希对 UTF-8 编码的原始片段计算 SHA-256，不偷偷统一换行。

relative_path 只使用 `/` 分隔，禁止绝对路径、空路径、NUL、`.` / `..` 段。path_key 在 Windows 按文件系统比较规则规范化，在大小写敏感系统保留大小写；它只用于唯一性，展示保留原始大小写。真正的文件授权仍须 realpath 与路径边界检查，数据库 CHECK 不替代文件系统安全。

JSON 字段（依据、修改列表、引用）由服务按 API schema 验证，设置长度 / 数量上限；当前 DDL 不假设所有 SQLite 版本都启用 JSON 扩展。外键必须在每个连接启用 `PRAGMA foreign_keys=ON`。

## 额外的服务层不变量

- 根目录只能由 VS Code 文件夹选择器登记；远端 API 不能自行增加任意系统目录。
- builtin 术语只读，项目自定义词优先；同名别名冲突要显示歧义，不能静默随机选择。
- term_id 被知识实体引用时，术语必须是全局内置或同项目自定义；跨项目词条拒绝。
- 修复预览的 diagnostic_id 与 file_id 必须指向同一文件；fix_history.file_id / preview_id 是审计快照引用，删除文件后保留标题而不读遗留路径。
- 向量长度必须等于 dimension × 浮点编码字节数；同一检索索引只能混用明确兼容的模型 / 维度。
- KB 相对路径必须位于专属知识目录；不允许把同步写入任意源码路径；删除项目只删除元数据，删除 Markdown 正文需要独立确认。

## 删除与保留

删除项目级元数据可级联到根、索引、笔记、图谱、对话；UI 必须先说明笔记会被删除。**绝不因此删除源文件。** 文件暂时消失时先设 missing，保留笔记与证据；只有显式清除索引才触发外键级联。修复记录、同意记录设置保留期；API 密钥仅进入 VS Code SecretStorage。

## 从 v0.1 / v0.2 迁移

原库先完整备份 → 新库事务建表 → 登记允许的项目根 → URI 映射到文件 ID → 校验快照和位置 → 导入笔记 / 修复历史 → 比较条数、内容哈希与外键 → 写入迁移结果 → 切换读取。无法归属的笔记放入待认领列表，不能丢弃。任何一步失败，保留原库继续使用。回滚通过切回原文件实现，不反向破坏新库。
