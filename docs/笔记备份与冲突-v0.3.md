# v0.3 实现说明：笔记备份、恢复与并发保护

普通使用者只需读《新手从这里开始》第四节。本文件记录已经实现的本地功能；OpenAPI 和 schema-v2.sql 仍是未来设计。

## 使用流程与入口

界面保持四步引导。打开带 .zhima-practice.json 标记的练习时，首次自动跳到“读懂一句”；用户之后主动返回第一步会保留选择。

“我的笔记”标题栏增加备份与恢复按钮。命令面板也能用中文找到相同操作。

| 命令 ID | 用户看到的名称 | 实际动作 |
| --- | --- | --- |
| zhima.exportNotes | 知码：备份我的笔记 | 选择一个已打开的项目根目录，导出笔记到用户选定的本地 JSON 文件 |
| zhima.importNotes | 知码：从备份恢复笔记 | 选择备份、选择当前项目、决定冲突策略、预览、确认后批量写入 |

对话框取消不写入。恢复不修改源码。每次仅处理一个根目录；多个根目录分别备份。项目根文件夹可以改名，根目录下的相对路径需保持一致。

## 运行库（与未来规范库区分）

| 表 | 字段 | 用途 |
| --- | --- | --- |
| notes | id 主键、uri、body | body 是笔记 JSON；uri 建索引 |
| history | id 自增主键、body | 原有修复记录，读取最近 30 条 |
| note_revisions | id 主键、revision 整数 | 持续递增的笔记版本，删除后保留版本记录，避免恢复同 ID 后旧窗口覆盖 |

Note 字段为 id、uri、start、end、selectedText、codeHash、content、createdAt、updatedAt、status、author、revision。位置采用 UTF-16 偏移，end 不包含末尾字符。状态 active 表示唯一精确匹配；stale 表示等待用户重新选择。codeHash 是原始代码片段 UTF-8 的 SHA-256，保留 CRLF 与 emoji。

旧库没有 revision 的笔记在读取时视为 1；首次写入保存新的版本。不会执行未来规范库迁移，也不会改动旧笔记正文。升级后应让所有打开的窗口启用新版；旧 v0.2 窗口不具备并发版本检查。

## 本地存储 API

| 方法 | 行为 |
| --- | --- |
| list(uri?) | 返回最新笔记，包含 revision |
| put(note) | 新增时不带 revision；修改时带读取所得 revision；返回实际保存的新版本 |
| delete(id, expectedRevision) | 版本相同才删除，同时增加保留的版本记录 |
| previewImport(notes, policy) | 只读预览 added / duplicates / conflicts / copies |
| importNotes(notes, policy) | 在独占锁内重新读取库、重算冲突、单次事务写入、导出临时文件并替换原库 |

revision 不匹配，或修改时记录已删除，会抛 NoteConflictError；UI 刷新列表，编辑操作另外打开含用户输入的未保存草稿。删除与重新选择代码也检查版本。自动更新位置失败只记录日志，下一次刷新重试，不让笔记写入故障伪装成解析失败。

policy 为 skip（保留当前记录）或 keepBoth（为不同内容生成新 ID）。相同 uri、片段、哈希、正文和作者视为重复，避免再次导入生成相同副本。确认期间另一窗口增加笔记时，在写入锁内重算并报告实际数量。批次失败不替换原数据库。

## 可移植备份格式 v1

```json
{
  "kind": "zhima-notes",
  "version": 1,
  "createdAt": "2026-09-24T00:00:00.000Z",
  "projectName": "我的项目",
  "notes": []
}
```

notes 的每项保存 Note 的正文、快照、时间、作者、状态和偏移；用 path 代替绝对 uri，并省略 revision。path 示例：backend/service.py。projectName 仅用来显示，不能指定磁盘路径。恢复时只使用用户在 VS Code 已打开的目标根目录。备份不含完整源码、修复历史、词典与设置。

验证要求：最多 10 MB / 5000 条；单条正文最多 10000 字符，快照最多 100000 字符；ID 必须唯一；时间可解析；偏移为合法整数且长度与快照一致；快照哈希匹配。未知格式版本、损坏行或不安全路径拒绝整份备份。未知字段不进入运行库。

路径只接受相对路径与正斜杠，禁止绝对路径、反斜杠、冒号、控制字符、空段、点段、上级目录、Windows 保留设备名和末尾空格 / 点。后缀限 .py / .html。恢复再次检查真实路径，拒绝跳出根目录的链接，并应用当前忽略规则与文件大小限制。

文件缺失、被忽略、无法读取或超限时列为跳过；不删除备份条目，也不写入假笔记。代码变化或不唯一时保留正文并标为 stale。最终确认前后两次解析目标文件；准备结果变化时取消，请用户重新预览。

## 本版保留的限制

- 崩溃遗留的锁仍需关闭所有知码窗口后人工处理；未自动判断并清除锁所有权。
- 文件系统与数据库不是一个事务；确认后发生的外部源码修改会在下次打开 / 刷新时重新核对定位。
- 尚未自动认领缺失文件、搜索改名文件或模糊匹配片段。
- 不自动上传备份、不自动同步电脑、不迁移未来规范数据库。
