# 技术修订 v2.1

日期：2026-09-24。对应当前实现 v0.2.0；设计契约不等于功能已上线。此前 roadmap-gap-analysis.md 保留为历史评审，以本文件和开发任务中的实际状态为准。

## 关键更正

| 原文中的问题 | 修订决定 | 影响 |
| --- | --- | --- |
| 所有功能都标 P0，同时又说分期 | 以“本次可安装闭环”排序；地图、沙盒、AI、团队协作后置 | 第一版不要求服务端和账号 |
| 使用者先 npm install、启动后端 | 普通用户只安装 VS Code 与知码安装包；Windows 提供双击助手与手动备用步骤 | 开发环境与使用环境分开 |
| NestJS / Prisma / React 都作为首期必需 | 当前插件内服务 + 原生面板 + 引导 Webview；SQLite 用 sql.js | 后续 API 可复用服务，不为架构而增加安装步骤 |
| WASM 组件列“三件套”，实际列四个文件 | 随包四个 WASM：Tree-sitter 核心、Python、HTML、SQLite | 打包校验必须逐个验证存在 |
| Promise.race 可强制结束执行 | 它只结束等待；独立 Worker 超时后必须 terminate，并丢弃会话 | 不把超时返回当作代码停止 |
| Worker 内创建 iframe | Worker 没有 DOM；HTML 预览在 Webview 的受限 iframe 内 | 执行与渲染使用不同边界 |
| WASM 天然禁网、绝对无法接触文件 | 能力取决于宿主暴露的桥接和挂载；禁止暴露宿主文件接口，CSP / 网络能力单独测试 | 不能用“WASM”代替安全证明 |
| 每 100ms 看内存即可硬限制 256MB | 采样存在窗口，不能承诺硬限制；先验证引擎或进程限制机制，否则声明只有限时 | 不上线虚假的内存保证 |
| 把工具名 treesitter_analyze_file 当标准 API | 使用实际库 Parser.init / Language.load / AST 遍历 | 版本锁定并针对语法样本测试 |
| path.resolve + startsWith 足以检查路径 | 使用规范化后的真实路径、路径段边界、文件类型和大小；读取前复核，避免符号链接与 TOCTOU | API 不接收任意根路径 |
| 标注仅保存行号 | 保存文件身份、半开区间、UTF-16 偏移、快照与哈希；唯一匹配才迁移 | 匹配含糊时请求人工重选 |
| 语法树 = 类型检查 = 业务理解 | 三者分开；当前只做语法与保守结构规则 | 结果要包含依据、范围和限制 |
| 一键修复根据错误名直接替换 | 先生成精确修改、对比、版本校验，再由用户应用 | 拒绝过期修复，保持可撤销 |
| localhost API 只要有 Token 就安全 | 若启用，随机端口、仅回环绑定、每次启动随机令牌、拒绝无许可 Origin / Host、请求大小限制 | 当前版没有 HTTP 监听端口 |
| SQLite 快照不会有并发问题 | 当前整库快照写锁只解决丢整库更新；同条笔记仍需版本冲突检查 | 未来规范模型增加 version 与 If-Match |
| 相对文件路径在多根目录中唯一 | 唯一键必须包含 project_id + root_id + relative_path；Windows 另存规范化比较键 | 避免同名文件串项目 |

## 已实现与设计边界

v0.2.0 使用 v0.1 的 notes/history SQLite 表，不自动执行新的 schema-v2.sql。引导进度写入 VS Code workspaceState，最后练习位置写入 globalState。当前仍然按打开的文件分析，不运行代码、不调用 AI、不提供远程同步。

本次补充的 schema-v2.sql、openapi-v1.json 是后续研发的可校验设计契约：已经通过结构测试不代表已经接入实际插件。新增 HTTP 层必须单独开发、鉴权和集成测试。

## 执行边界与未来安全验收

Python 沙盒：独立 Worker；仅传入用户确认的片段与 JSON 参数；每次执行单独会话；超时终止 Worker；限制 stdout/stderr 总量；默认不开放网络、包安装和宿主文件。Worker 使用的脚本、WASM 和 CSP 在离线与联网两种环境下验证。SharedArrayBuffer / 中断缓冲依赖宿主隔离配置，不能假设在所有 VS Code Webview 可用。未能实施严格内存上限时不得对外承诺。

HTML 预览：Webview iframe；默认无 allow-scripts、无 allow-same-origin；不允许外部资源、表单提交、顶层跳转、弹窗、下载。需要交互脚本时另建受限模式与安全测试，不能放宽默认策略。

云端 AI：先展示将发送的片段、路径和上下文，用户同意后发送；不自动递归上传项目；密钥保存在 SecretStorage；响应引证具体文件与行号，并标注不确定性。用户可取消且不记录密钥或全文源码日志。

## 数据迁移与回滚

新增规范数据库使用新文件，不覆盖 notes.sqlite。迁移前关闭写入并备份原文件；校验旧快照哈希；根据允许的根目录映射旧绝对 URI 到 root_id / 相对路径；不能映射的笔记进入“待人工认领”，不丢弃。迁移在一个事务中进行，记录 old_id → new_id 和迁移版本；失败回滚新库。通过笔记数量、内容哈希、外键检查和抽样定位后再切换读取入口；至少保留一次版本的旧库备份。
